# AES67-мост LinkTalk → пульт → Riedel

Встроен в LinkTalk Bridge (Windows/macOS), отдельный Docker, ВМ и платная виртуальная Dante-карта не нужны.

```
LinkTalk ──Opus/RTP──> Bridge ══AES67 (multicast, L24, 48 кГц)══> пульт ──аналог 4-wire──> Riedel
LinkTalk <──Opus/RTP── Bridge <═AES67════════════════════════════ пульт <──аналог 4-wire── Riedel
```

Одна линия = один моно-канал в каждую сторону = один 4-wire порт Riedel.
Схема на 8 слотов × 8 каналов даёт до 64 линий.

## 1. Пульт / Dante

1. Включите AES67 на пульте. У устройств Dante: Dante Controller → Device View → вкладка *AES67* → Enable,
   затем перезагрузка устройства. После этого Dante-устройства работают на PTPv2, домен 0.
2. Пульт (или другой узел сети) должен быть PTP-мастером. Без мастера мост шлёт звук, но временные метки
   «плавают» и приёмники AES67 могут отбрасывать пакеты.
3. На приёмнике (пульте) увеличьте задержку для AES67-потоков до 4–5 мс: программные PTP-метки и планировщик
   Windows дают джиттер около миллисекунды.
4. Коммутатор: IGMP snooping + querier (или отключите фильтрацию мультикаста на портах пульта и ПК).

## 2. Bridge

1. Закрепите сетевой адаптер ПК, смотрящий в AES67/Dante-сеть. Если это не адаптер по умолчанию, укажите его IP
   в `aes67.json` (`interface`).
2. Разрешите в Windows Firewall UDP 319, 320, 5004 и 9875 (при первом запуске Windows спросит сама).
3. В Bridge в строке *AES67 Audio* должно быть `PTP <ID мастера> (… µs)` и число найденных потоков.
4. В админке LinkTalk создайте для каждой линии служебного пользователя (раздел *Bridge*), назначьте:
   * выход: `AES67 network output · LinkTalk Bridge N`, канал `1`, `2`, `3`… (моно) — звук абонента LinkTalk уходит в пульт;
   * вход: `AES67 network input · <поток пульта>`, нужный канал — звук из Riedel приходит абонентам.
5. На пульте подпишитесь на поток `LinkTalk Bridge N` и направьте каналы на аналоговые выходы → в 4-wire порты Riedel.
   Обратное направление: аналоговые входы пульта → AES67-поток пульта (его Bridge увидит сам через SAP).

## 3. `aes67.json` (необязательный)

Путь виден во всплывающей подсказке строки *AES67 Audio*:
Windows `%APPDATA%\LinkTalk Bridge\aes67.json`, macOS `~/Library/Application Support/LinkTalk Bridge/aes67.json`,
либо переменная `LINKTALK_AES67_CONFIG`. Все поля необязательны, интерфейс и PTP-домен применяются после перезапуска Bridge.

```json
{
  "interface": "192.168.50.20",
  "ptp_domain": 0,
  "output_channels": 8,
  "output_base": "239.69.50",
  "payload_type": 97,
  "sap_announce": true,
  "sources": [
    { "name": "Console Out", "multicast": "239.69.20.1", "port": 5004, "channels": 8, "bits": 24, "payload_type": 97 }
  ]
}
```

* `output_base` задаёт группы отправки `239.69.50.<слот>:5004`; без него третий октет берётся из имени компьютера.
* `sources` нужен для потоков, которые пульт не анонсирует по SAP. Параметры берутся из SDP потока.
* Если пульт не видит наши потоки по SAP, подпишите его вручную: группа `output_base.слот`, порт 5004,
  кодек L24/48000, число каналов `output_channels`, ptime 1 мс.

## 4. Ограничения

* Код написан без доступа к компилятору Rust и реальному оборудованию: перед боевым использованием соберите Bridge
  (`cd bridge-client && cargo check && cargo test` в `src-tauri`) и проверьте с вашим пультом.
* PTP использует программные метки времени (без аппаратной поддержки сетевой карты): точность порядка сотен
  микросекунд, для интеркома достаточно, но это не замена GPS/PTP-оборудованию в вещании.
* Поддерживаются только L24/L16, 48 кГц, пакеты 125 мкс–4 мс на вход и 1 мс на выход.
* Задержка тракта в одну сторону около 15–30 мс вместе с Opus.
