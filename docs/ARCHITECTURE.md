# Архитектура сервера LinkTalk

Сервер раньше был одним файлом `src/server/serverCore.js` (9300 строк). Теперь это 29 секций, которые
загружаются **строго в прежнем порядке**, поэтому поведение при старте не изменилось.

```
src/server/
  serverCore.js        — точка входа: по очереди подключает секции
  ns.js                — реестр секций (ns.<секция>.<имя>)
  core/                — состояние и логика (сессии, цели разговора, статус админки, медиа, запуск)
  routes/              — HTTP-маршруты Express
  socket/              — обработчики Socket.IO (подключение клиентов)
  (прочие файлы)       — небольшие самостоятельные модули: db, dbHandler, monitoring, webAccess…
```

## Порядок секций и зависимости

Порядок задан в `serverCore.js` и важен: именно в нём секции выполняют свой верхний уровень
(создают `app`, регистрируют маршруты, запускают сервер).

* Секция может **деструктурировать** имена из секций, загруженных **раньше**:
  `const { requireAdmin } = ns.sessions;` — безопасно, секция уже полностью выполнена.
* К именам из секций, загружаемых **позже**, обращаются **в момент вызова**:
  `ns.entityNotifications.notifyTargetChange(...)`.
* Изменяемые глобальные переменные (`worker`, `router`, `companionNamespace`, `publicDir`, `monitorLinks`…)
  лежат прямо на `ns.<секция>` — читать и писать их нужно как `ns.mediaInit.worker`.
* Каждая секция в конце публикует то, чем пользуются другие: `Object.assign(ns.<секция>, { … })`.

### Как добавить маршрут

1. Найдите секцию по теме (`routes/routesUsers.js`, `routes/routesBridge.js`, …) или создайте новый файл.
2. Зарегистрируйте маршрут через `app` (из `ns.base`), а нужные функции деструктурируйте из ранних секций.
3. Новый файл подключите в `serverCore.js` и добавьте ключ в `ns.js`.
4. Порядок регистрации маршрутов важен там, где пути пересекаются (например `/users/:id` и `/users/order`).

## Совместимость со старыми установками

| Что | Как работает |
|---|---|
| Переменные `TALKTOME_*` | `envAliases.js` подставляет значение в `LINKTALK_*`, если новая не задана |
| Cookie `talktome_session` | сервер читает обе cookie, выдаёт `linktalk_session`, при выходе сбрасывает обе |
| Папка данных `talktome` | если есть и новой нет — используется старая (`dataPaths.js`) |
| Файл конфигурации `talktome-config` | импорт принимает старый и новый формат |
| Резервные копии `talktome-config-auto-*` | учитываются при подсчёте наравне с новыми |
| Приложение Android | ключи `talktome.*` переносятся в `linktalk.*` при первом запуске, cookie и ссылки `talktome://` принимаются |

## Тесты

Часть тестов читает исходники сервера как текст. Они используют `tests/helpers/serverSource.js`, который
склеивает все секции в порядке загрузки и подставляет `ns` для вырезок кода в `vm`.
